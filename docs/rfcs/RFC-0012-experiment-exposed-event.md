# RFC-0012 — افزودن رویداد `experiment_exposed` به AppEvent

- **نویسنده:** AI-12
- **تاریخ:** 2026-08-18
- **وضعیت:** 🟡 در انتظار بررسی
- **نوع:** تغییر contracts

## مشکل
پرامپت AI-12 آزمایش A/B سبک را الزام می‌کند (`getVariant(experimentId): 'A' | 'B'`).
برای تحلیل درست هر آزمایش، باید بدانیم هر anonId **کی و با کدام variant** در معرض
آزمایش قرار گرفته (قاعده‌ی استاندارد exposure logging). union فعلی `AppEvent` در
`packages/contracts/src/events.ts` (§5) چنین رویدادی ندارد؛ بنابراین `analytics.track(e)`
تایپ‌شده نمی‌تواند آن را حمل کند.

## پیشنهاد
افزودن یک عضو به union `AppEvent`:

```ts
| { type: 'experiment_exposed'; experimentId: string; variant: 'A' | 'B' }
```

بدون وابستگی جدید؛ صرفاً یک عضو union. مصرف‌کننده‌ی اصلی: analytics (خودش تولید
و مصرف می‌کند)؛ app-shell در صورت نیاز می‌تواند برای گیت‌کردن UI به آن گوش دهد.

## جایگزین بدون‌وابستگی بررسی‌شده
**راهکار موقت فعلی (تا تأیید):** analytics رویداد exposure را در قالب سیمی ژنریک
خودش (`WireEvent { event: 'experiment_exposed', payload: {experimentId, variant} }`)
مستقیماً صف می‌کند — بدون عبور از تایپ `AppEvent` و بدون نقض قرارداد. کار می‌کند،
اما این رویداد از دید سایر مصرف‌کنندگان EventBus (مثلاً QA در تست قرارداد) پنهان
می‌ماند و از union تایپ‌سیف خارج است. پذیرش RFC آن را رسمی و تایپ‌سیف می‌کند.

## پکیج‌های متأثر
- `packages/contracts` (یک عضو union جدید — تغییر افزایشی و backward-compatible)
- `packages/analytics` (پس از تأیید: ارسال از مسیر تایپ‌شده‌ی `track(e: AppEvent)`)

## مهاجرت
تغییر افزایشی است؛ هیچ مصرف‌کننده‌ای نمی‌شکند. تنها نکته: switch های exhaustive
روی `AppEvent['type']` (در صورت وجود در پکیج‌های دیگر) باید case جدید را اضافه کنند.
پس از تأیید، AI-12 مسیر موقت ژنریک را حذف و از union رسمی استفاده می‌کند
(قالب سیمی خروجی تغییری نمی‌کند — سرور/تحلیل ناسازگار نمی‌شود).
