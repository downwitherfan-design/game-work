## بخش ۰ — چه اتفاقی افتاد؟ (تشخیص، نه سرزنش)

APK ساخته شد، امضا شد، نصب شد — و **کار نمی‌کرد**. مالک محصول این جمله را نوشت:

> «بازی رو نصب کردم و واقعا آشغال و مزخرف بود! … این همه تلاش منتهی به این اپ مسخره شده؟»
>
> «بازی باید یه منوی اصلی، یه تنظیمات یه مراحل یه اینجوری چیزا داشته باشه، **شبیه یه اپ واقعی**»

نکته‌ی دردناک: **۱۱۲۱ تست سبز بود.** هر ۱۵ پکیج تست خودش را پاس می‌کرد. یعنی
مشکل در «کیفیت پکیج‌ها» نبود؛ مشکل در **یکپارچه‌سازی** بود. سه باگ ریشه‌ای:

| # | باگ | چرا تست‌ها نگرفتند؟ |
|---|-----|---------------------|
| ۱ | `app-shell` هرگز `engine`/`audio`/`bus` را به `GameScreen` تزریق نمی‌کرد → `game-board` به Mock داخلی خودش سقوط می‌کرد | هر پکیج Mock خودش را تست می‌کرد، هیچ‌کس «اتصال» را تست نمی‌کرد |
| ۲ | `Onboarding` مستقیماً `MockGameScreen` را import می‌کرد | تست فقط رندر شدن را چک می‌کرد، نه اینکه *کدام* کامپوننت |
| ۳ | CSS دیزاین‌سیستم (`tokens.css` + `ui-kit.css`) و `GAME_BOARD_CSS` هرگز در اپ واقعی تزریق نمی‌شدند (فقط در `demo`) | تست‌های CSS فایل را با `readFileSync` می‌خواندند، نه از مرورگر |

نتیجه: کاربر یک صفحه‌ی سفید با متن «این بخش هنوز آماده نیست» دید.

### 🔴 ضدالگوی اصلی که همه باید بشناسند: **Mock-Fallback خاموش**

در سراسر پروژه این الگو تکرار شده است:

```ts
// ❌ ضدالگو — خرابی را پنهان می‌کند
const engine = props.engine ?? resolveEngine();   // اگر تزریق نشود → Mock
const C = mod[name] ?? MockScreen;                 // اگر export نباشد → Mock
```

این الگو **باگ سیم‌کشی را به یک «ویژگی» تبدیل می‌کند**: اپ خراب نمی‌شود، فقط
بی‌سر‌و‌صدا آشغال می‌شود. **از این لحظه ممنوع است** (بخش ۲، قانون ق-۱).

## بخش ۲ — قوانین جدید و غیرقابل‌مذاکره (برای همه‌ی ۱۵ AI)

### ق-۱ — Mock فقط در تست. در کد محصول، خرابی باید **بلند** باشد.

```ts
// ✅ درست
if (!props.engine) throw new Error('[game-board] engine تزریق نشده است');

// ✅ یا در مرز lazy-load
const C = mod[name];
if (typeof C !== 'function') throw new Error(`[app-shell] export گمشده: ${name}`);
```

Mockها باید در `src/mocks/` بمانند و **فقط** از فایل‌های `test/` و `demo/` import شوند.
هر مسیر `?? Mock…` در کد محصول یک باگ P0 است.

### ق-۲ — «تست پکیج سبز» معیار تمام‌شدن **نیست**.

معیار تمام‌شدن یک کار = **در اپ نصب‌شده روی گوشی کار می‌کند**. اگر کار شما در
`app-shell` قابل مشاهده نیست، تمام نشده است.

### ق-۳ — هر پکیج UI باید CSS خودش را «قابل تزریق» و **مستند** کند.

اگر CSS شما رشته است (مثل `GAME_BOARD_CSS`)، در README پکیج با حروف درشت بنویسید
که مصرف‌کننده باید تزریقش کند — و در `app-shell` **خودتان** PR بزنید که تزریق شود.

### ق-۴ — مرز مالکیت گرافیک ↔ چیدمان (مهم: تعارض واقعی رخ داده است)

| قلمرو | مالک | شامل |
|-------|------|------|
| **ظاهر** | **AI-04** | رنگ، توکن، بافت چوب/کاشی، گرادیان، سایه، آیکون، فونت، انیمیشن |
| **چیدمان** | **AI-05 / AI-06** | اینکه چه چیزی در نمای گوشی جا شود، flex/grid، اندازه‌ی خانه، اسکرول |

- AI-04 **نباید** `min-block-size`/`grid-template`/`flex` صفحه‌ی بازی را عوض کند.
- AI-05/06 **نباید** hex رنگ بنویسند — فقط `var(--dor-*)` مصرف کنند.
- 🚫 **هیچ‌کس hex رنگ را در تست قفل نکند.** تست کنتراست باید *قاعده* را بسنجد
  («نسبت ≥ ۴.۵»)، نه *مقدار* را («باید `#f7f3e9` باشد»). قفل‌کردن hex باعث شد
  بازطراحی معتبر AI-04، ۳۳ تست را بشکند.

### ق-۵ — APK **فقط و فقط** در GitHub Actions ساخته می‌شود.

هرگز در سندباکس. Gradle+R8 به ۲–۳ گیگابایت RAM نیاز دارد؛ سندباکس ~۹۸۵ مگابایت دارد.
