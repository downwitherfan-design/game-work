# ⛔ خطوط قرمز مطلق پروژه‌ی دُردانه
### این سند بر هر دستور دیگری اولویت دارد. نقض هر بند = رد شدن کار.

---

## 🔴 دسته‌ی ۱ — مالکیت کد (ضد تداخل موازی‌کاری)

1. **فقط در مسیرهای مالکیت خودت بنویس.** هر AI فقط حق ایجاد/ویرایش/حذف فایل در دایرکتوری‌های مالکیت خودش (طبق جدول بخش ۷ سند `00_MASTER_PLAN.md`) را دارد. **حتی یک کاراکتر** خارج از آن ممنوع است.
2. **`packages/contracts/` مقدس است.** هیچ AI (به‌جز از طریق RFC تأییدشده) حق تغییر آن را ندارد. اگر قرارداد ناقص است: فایل `docs/rfcs/RFC-XXXX-<title>.md` بساز، مشکل و پیشنهاد را بنویس، و **تا تأیید، با قرارداد فعلی کار کن** (در ماژول خودت آداپتور موقت بنویس).
3. **`package-lock.json` و فایل‌های ریشه‌ی مونوریپو** فقط مال AI-14 است. وابستگی جدید می‌خواهی؟ RFC بده.
4. **اسناد `docs/00`، `docs/01`، `docs/02` فقط-خواندنی‌اند** (تغییر فقط توسط مدیر پروژه).
5. **از پکیج دیگران فقط import از entry point رسمی** (`@dordaneh/<pkg>`) مجاز است. import از مسیر داخلی (`../other-pkg/src/...`) ممنوع.
6. **نمودار وابستگی یک‌طرفه را نشکن.** فقط وابستگی‌های مجاز بخش ۲ مسترپلن. وابستگی حلقوی = رد کار.

## 🔴 دسته‌ی ۲ — گیت و گردش کار

7. کامیت‌های کوچک با پیام Conventional Commits: `feat(scope): ...`، `fix(scope): ...`. push فوری بعد از هر کامیت.
8. قبل از شروع هر جلسه‌ی کاری: `git pull --rebase origin main`.
9. **هرگز force-push به `main`.** هرگز history بازنویسی نکن.
10. هرگز فایل باینری بزرگ (>500KB) کامیت نکن؛ صدا/تصویر بهینه‌شده و کوچک باشد.
11. هرگز secret، توکن، keystore یا API key در ریپو نگذار.

## 🔴 دسته‌ی ۳ — طراحی محصول (از سند راهبردی مصوب)

12. **هرگز pay-to-win.** هیچ خریدی نباید مزیت رقابتی در حل معما بدهد. فروش فقط: راحتی (بدون تبلیغ، Streak Freeze)، محتوا (بسته‌های موضوعی) و ظاهر (تم).
13. **هرگز تبلیغ اجباری.** فقط Rewarded با رضایت. **هرگز هیچ تبلیغی در جلسه‌ی اول کاربر.**
14. **هرگز ثبت‌نام/لاگین اجباری.** هویت ناشناس (UUID محلی) پیش‌فرض است.
15. **هرگز استریک بی‌رحم.** Streak Freeze از MVP وجود دارد.
16. **هرگز Feature Creep.** فقط فیچرهای فاز جاری. ایده‌ی جدید → RFC، نه کد.
17. کاربر باید در **۳۰ ثانیه‌ی اول** به لذت/پیروزی برسد.
18. **حالت آفلاین-اول:** بازی روزانه و تمرین باید کاملاً بدون اینترنت کار کند (معماها به‌صورت deterministic از seed محلی تولید می‌شوند؛ سرور فقط sync است).

## 🔴 دسته‌ی ۴ — فنی

19. **TypeScript strict** در همه‌ی پکیج‌ها؛ `any` ممنوع (مگر با کامنت توجیهی).
20. `core-engine` باید **خالص (pure) و بدون وابستگی به DOM/شبکه** بماند — فقط توابع و کلاس‌های قطعی (deterministic) و تست‌پذیر.
21. **متن فارسی:** همیشه از توابع نرمال‌سازی `@dordaneh/contracts` استفاده کن؛ هرگز نرمال‌سازی محلی خودت را ننویس.
22. **هیچ رشته‌ی متنی هاردکد در UI؛** همه از `locales/fa.json` پکیج خودت (قرارداد i18n در `02_CONTRACTS.md`).
23. **بودجه‌ی حجم:** سهم هر پکیج UI از باندل ≤ ۱۵۰KB (gzip). کتابخانه‌ی سنگین ممنوع بدون RFC. کل اپ اندروید < ۳۰MB.
24. **RTL-first:** همه‌ی layout ها با `dir="rtl"` طراحی و تست شوند؛ از خصوصیات logical CSS (`margin-inline-start` و…) استفاده کن.
25. رنگ/فونت/فاصله فقط از توکن‌های `@dordaneh/ui-kit` (یا CSS variables قرارداد). مقدار hex هاردکد ممنوع.
26. هر PR باید تست داشته باشد و `npm run build && npm test` سبز باشد. تستِ قرمز = مرج ممنوع.
27. **پاسخ UI < 100ms** برای هر تعامل؛ انیمیشن‌ها با CSS transform/opacity (نه layout thrash).
28. حریم خصوصی: هیچ داده‌ی شخصی (شماره، ایمیل، مخاطبین) جمع نکن. آنالیتیکس فقط رویدادهای ناشناس.

## 🔴 دسته‌ی ۵ — محتوا

29. هیچ واژه یا محتوای توهین‌آمیز، سیاسی، مذهبیِ حساس یا جنسی — نه در دیتابیس کلمات، نه در کارت‌های فرهنگی. محتوا باید «امنِ خانوادگی» و قابل انتشار در کافه‌بازار باشد.
30. کارت‌های فرهنگی باید **دقیق و مستند** باشند (منبع هر شعر/ضرب‌المثل در فیلد `source` ثبت شود). اطلاعات غلط = رد کار.
31. متن‌های فارسی UI: لحن گرم، محاوره‌ی مودبانه («آفرین! زدی وسط خال 🎯»)، نیم‌فاصله‌ی درست (ZWNJ)، اعداد فارسی در نمایش.
